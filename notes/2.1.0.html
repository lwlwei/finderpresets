Names and keywords

  • A prompt for presets that ask for a name. It lists the folders that fit as you type (best match first, each told apart by the [x] folder it is in); ↑↓, a click or Return choose; it starts from the folder you opened last time, so reopening a project is one Return. The second "which folder?" question is gone, and a name left without a value is asked for instead of ending in "folder not found".
  • The best match wins under [x]. Typing "ray" opens "ray gunn" in a later [x] folder, not "gray house" in an earlier one; "Ask which folder when a keyword matches more than one" now also works for [x] paths and for side bar rows.
  • Command palette: type a preset's name and a keyword ("clients ray") and pick the folder right there; ⌘Return shows it in Finder, ⌥Return copies its path.
  • Kinder matching. Accents, full-width letters and simplified/traditional characters make no difference, and a Chinese folder name can be found by its pinyin ("kehu" or "kh").
  • Side bar rows and the preset editor show how many folders a keyword fits ("≡ 3" with a menu to pick one; "3 folders fit: …" under a fixed value). Presets that ask end in "…" in the menu bar.

Stability

  • Nothing waits for a disk that does not answer. Quick Jump opens at once, the editor's folder previews are read in the background, and a folder that does not answer when a preset opens is skipped with a notice instead of freezing the app.
  • One damaged record no longer costs the whole list. Presets, side bar rows, folder templates and app groups are read one by one: the readable ones load, the original is kept aside, and you are told.
  • Settings search finds a setting by its name (the Opening and Side Bar pages were only found by two or three titles).
